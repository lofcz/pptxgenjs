### Charts: flat string categories are always written as <c:multiLvlStrRef>; single-level categories should use <c:strRef> (labels fall back to 1,2,3ΓÇª in some importers)`n**Version:** 4.0.1 (also present in current `master` `src/gen-charts.ts`)

## Issue

When a chart has string category labels, `genXmlChartData` always emits the category axis data (`<c:cat>`) as `<c:multiLvlStrRef>` ΓÇö even when the categories are a flat, single-level list. There is no code path that emits `<c:strRef>` for string categories:

```js
strXml += `    <c:f>Sheet1!$A$2:$${getExcelColName(obj.labels.length)}$${obj.labels[0].length + 1}</c:f>`;
strXml += '    <c:multiLvlStrCache>';
...
```

Per ECMA-376, `<c:multiLvlStrRef>` is intended for hierarchical (multi-level) category axes. PowerPoint itself writes flat string categories as `<c:strRef>`/`<c:strCache>`, and that is what most third-party OOXML chart parsers implement.

## Impact

PowerPoint handles `multiLvlStrRef` fine, but several importers/renderers do not implement the `multiLvlStrRef`/`<c:lvl>` structure and silently fall back to sequential numbers, so a chart created with `categories: ["Q1","Q2","Q3","Q4"]` renders with category labels `1, 2, 3, 4` instead. ## Repro

```js
const pptxgen = require("pptxgenjs");
const pptx = new pptxgen();
const slide = pptx.addSlide();
slide.addChart(pptx.ChartType.bar, [
  { name: "Sales", labels: ["Q1", "Q2", "Q3", "Q4"], values: [120, 135, 150, 180] },
], { x: 1, y: 1, w: 8, h: 4 });
pptx.writeFile({ fileName: "repro.pptx" });
// unzip repro.pptx ΓåÆ ppt/charts/chart1.xml contains <c:multiLvlStrRef> under <c:cat>
```

## Suggested fix

In the `<c:cat>` block of `genXmlChartData`, emit `<c:strRef>`/`<c:strCache>` when `obj.labels.length === 1`, and keep the existing `<c:multiLvlStrRef>` output for genuinely multi-level labels (`obj.labels.length > 1`):

```js
if (obj.labels.length === 1) {
    strXml += '  <c:strRef>';
    strXml += `    <c:f>Sheet1!$A$2:$A$${obj.labels[0].length + 1}</c:f>`;
    strXml += '    <c:strCache>';
    strXml += `      <c:ptCount val="${obj.labels[0].length}"/>`;
    obj.labels[0].forEach((label, idx) => (strXml += `<c:pt idx="${idx}"><c:v>${encodeXmlEntities(label)}</c:v></c:pt>`));
    strXml += '    </c:strCache>';
    strXml += '  </c:strRef>';
} else {
    // existing multiLvlStrRef output
}
```

### Multiple errors in PowerPoint that were not in LibreOffice - with workarounds/fixes`n# PptxGenJS Defect List & Workaround Guide

**Discovered:** March 2026
**PptxGenJS Version:** 3.x (npm `pptxgenjs`)
**Context:** Generating a 55-slide executive briefing deck. PowerPoint (macOS, Microsoft 365) triggered "needs to be repaired" and "unreadable content" dialogs on every open. LibreOffice rendered the same files without error.

---

## Defect 1: Invalid Shape Preset ΓÇö `"oval"` written as literal string

**Severity:** High ΓÇö triggers "unreadable content was removed" dialog
**Affects:** Any slide using `addShape("oval", ...)`

### Problem

When passing the string `"oval"` to `addShape()`, PptxGenJS writes the literal value into the OOXML XML:

```xml
<a:prstGeom prst="oval">
```

The valid OOXML preset geometry type is `"ellipse"`, not `"oval"`. PowerPoint cannot parse `prst="oval"` and removes the shape during repair, converting it to a line.

### Evidence

```
pres.shapes.OVAL  // returns "ellipse"
```

PptxGenJS's own enum maps `OVAL` to `"ellipse"`, but passing the string `"oval"` bypasses the enum lookup and writes the raw string to XML.

### Workaround

Use the correct OOXML preset string:

```javascript
// WRONG ΓÇö generates invalid XML
slide.addShape("oval", { x: 1, y: 1, w: 0.4, h: 0.4, fill: { color: "00B0B9" } });

// CORRECT ΓÇö use the OOXML preset name
slide.addShape("ellipse", { x: 1, y: 1, w: 0.4, h: 0.4, fill: { color: "00B0B9" } });

// ALSO CORRECT ΓÇö use the enum constant
slide.addShape(pres.shapes.OVAL, { x: 1, y: 1, w: 0.4, h: 0.4, fill: { color: "00B0B9" } });
```

### Suggested Fix

`addShape()` should validate the shape type string against the known presets (or the internal shapes enum) and throw an error or map common aliases. At minimum, `"oval"` should map to `"ellipse"`.

---

## Defect 2: Invalid Shape Preset ΓÇö `"roundedRectangle"` written as literal string

**Severity:** High ΓÇö triggers "needs to be repaired" dialog
**Affects:** Any slide using `addShape("roundedRectangle", ...)`

### Problem

```
pres.shapes.ROUNDED_RECTANGLE  // returns "roundRect"
```

## Defect 3: Phantom `[Content_Types].xml` Overrides for Slide Masters

**Severity:** High ΓÇö triggers "needs to be repaired" dialog
**Affects:** Any presentation using `defineSlideMaster()` with more than a few slides

### Problem

PptxGenJS registers one `<Override>` entry in `[Content_Types].xml` per **slide** rather than per **actual slide master**. A 55-slide deck with 3 defined masters produces 55 `slideMaster` override entries:

```xml
<Override PartName="/ppt/slideMasters/slideMaster1.xml" ContentType="..."/>
<Override PartName="/ppt/slideMasters/slideMaster2.xml" ContentType="..."/>
<!-- ... -->
<Override PartName="/ppt/slideMasters/slideMaster55.xml" ContentType="..."/>
```

Only `slideMaster1.xml` actually exists on disk. The 54 phantom references trigger PowerPoint's repair process.

### Workaround

Post-process the PPTX after generation:

```javascript
const { execSync } = require("child_process");
const fs = require("fs");
const path = require("path");

function cleanContentTypes(tmpDir) {
  const ctPath = path.join(tmpDir, "[Content_Types].xml");
  let ct = fs.readFileSync(ctPath, "utf8");

  // Find which slideMaster files actually exist
  const mastersDir = path.join(tmpDir, "ppt", "slideMasters");
  const actualMasters = new Set();
  if (fs.existsSync(mastersDir)) {
    fs.readdirSync(mastersDir).forEach(function(f) {
      if (f.endsWith(".xml")) actualMasters.add(f);
    });
  }

  // Remove overrides for non-existent masters
  ct = ct.replace(
    /<Override\s+PartName="\/ppt\/slideMasters\/([^"]+)"[^>]*\/>/g,
    function(match, filename) {
      return actualMasters.has(filename) ? match : "";
    }
  );

  fs.writeFileSync(ctPath, ct);
}
```

### Suggested Fix

The Content_Types generation loop should iterate over the defined slide masters collection, not the slides collection.

## Defect 4: Unused Default Extension Types in `[Content_Types].xml`

**Severity:** Low ΓÇö does not trigger repair, but bloats the file and is non-conformant
**Affects:** All presentations

### Problem

PptxGenJS registers Default extension types for formats that are never used in the presentation:

```xml
<Default Extension="jpeg" ContentType="image/jpeg"/>
<Default Extension="jpg" ContentType="image/jpg"/>
<Default Extension="svg" ContentType="image/svg+xml"/>
<Default Extension="gif" ContentType="image/gif"/>
<Default Extension="m4v" ContentType="video/mp4"/>
<Default Extension="mp4" ContentType="video/mp4"/>
<Default Extension="vml" ContentType="application/vnd.openxmlformats-officedocument.vmlDrawing"/>
<Default Extension="xlsx" ContentType="application/vnd.openxmlformats-officedocument.spreadsheetml.sheet"/>
```

If the presentation only contains PNG images, only `png`, `xml`, and `rels` extensions are needed.

### Workaround

Post-process to remove unused extensions:

```javascript
function cleanExtensions(tmpDir) {
  const ctPath = path.join(tmpDir, "[Content_Types].xml");
  let ct = fs.readFileSync(ctPath, "utf8");

  const mediaDir = path.join(tmpDir, "ppt", "media");
  const usedExtensions = new Set(["xml", "rels"]);
  if (fs.existsSync(mediaDir)) {
    fs.readdirSync(mediaDir).forEach(function(f) {
      usedExtensions.add(f.split(".").pop().toLowerCase());
    });
  }

  ct = ct.replace(
    /<Default\s+Extension="([^"]+)"[^>]*\/>/g,
    function(match, ext) {
      return usedExtensions.has(ext) ? match : "";
    }
  );

  fs.writeFileSync(ctPath, ct);
}
```

### Suggested Fix

Only register Default extensions for media types actually embedded in the presentation.

## Defect 5: Malformed Notes Master with Invalid Placeholder Shapes

**Severity:** High ΓÇö triggers "needs to be repaired" dialog
**Affects:** All presentations (PptxGenJS always generates a notesMaster)

### Problem

PptxGenJS generates a `notesMaster1.xml` containing 6 placeholder shape definitions (Header, Date, Slide Image, Notes Body, Footer, Slide Number) that PowerPoint considers malformed. During repair, PowerPoint strips all 6 placeholders from the notes master, leaving an empty shape tree.

Additionally, the notesMaster's relationship file references `theme1.xml` (the presentation theme), but PowerPoint expects the notes master to have its own separate theme (`theme2.xml`).

### Evidence

Original notesMaster contains:
- Header Placeholder 1 (`type="hdr"`)
- Date Placeholder 2 (`type="dt"`)
- Slide Image Placeholder 3 (`type="sldImg"`)
- Notes Placeholder 4 (`type="body"`)
- Footer Placeholder 5 (`type="ftr"`)
- Slide Number Placeholder 6 (`type="sldNum"`)

After PowerPoint repair: all 6 are removed, shape tree is empty, and a new `theme2.xml` is created.

### Workaround

Strip the entire notes infrastructure in post-processing (if notes are not needed):

```javascript
function stripNotes(tmpDir) {
  // Remove notes files
  execSync("rm -rf " + JSON.stringify(path.join(tmpDir, "ppt", "notesMasters")));
  execSync("rm -rf " + JSON.stringify(path.join(tmpDir, "ppt", "notesSlides")));

  // Remove from Content_Types
  const ctPath = path.join(tmpDir, "[Content_Types].xml");
  let ct = fs.readFileSync(ctPath, "utf8");
  ct = ct.replace(/<Override\s+PartName="\/ppt\/notesMasters\/[^"]*"[^>]*\/>/g, "");
  ct = ct.replace(/<Override\s+PartName="\/ppt\/notesSlides\/[^"]*"[^>]*\/>/g, "");
  fs.writeFileSync(ctPath, ct);

  // Remove notesMasterIdLst from presentation.xml
  const presPath = path.join(tmpDir, "ppt", "presentation.xml");
  let presXml = fs.readFileSync(presPath, "utf8");
  presXml = presXml.replace(/<p:notesMasterIdLst>[\s\S]*?<\/p:notesMasterIdLst>/g, "");
  fs.writeFileSync(presPath, presXml);

  // Remove notesMaster relationship from presentation.xml.rels
  const presRelsPath = path.join(tmpDir, "ppt", "_rels", "presentation.xml.rels");
  let presRels = fs.readFileSync(presRelsPath, "utf8");
  presRels = presRels.replace(/<Relationship[^>]*notesMaster[^>]*\/>/g, "");
  fs.writeFileSync(presRelsPath, presRels);

  // Remove notesSlide relationships from each slide's .rels
  const slideRelsDir = path.join(tmpDir, "ppt", "slides", "_rels");
  if (fs.existsSync(slideRelsDir)) {
    fs.readdirSync(slideRelsDir).forEach(function(f) {
      if (f.endsWith(".rels")) {
        const rp = path.join(slideRelsDir, f);
        const content = fs.readFileSync(rp, "utf8");
        const cleaned = content.replace(/<Relationship[^>]*notesSlide[^>]*\/>/g, "");
        if (cleaned !== content) fs.writeFileSync(rp, cleaned);
      }
    });
  }
}
```

### Suggested Fix

Either: (a) generate a conformant notesMaster with its own theme, or (b) provide an option to disable notes generation entirely.

## Defect 6: Empty `charts/` and `embeddings/` Directories

### Problem

PptxGenJS creates empty `ppt/charts/_rels/` and `ppt/embeddings/` directories in every PPTX file, even when no charts or embedded objects are present. While not strictly invalid, these empty scaffolding directories are unnecessary and are removed during PowerPoint repair.

### Workaround

```javascript
execSync("rm -rf " + JSON.stringify(path.join(tmpDir, "ppt", "charts")));
execSync("rm -rf " + JSON.stringify(path.join(tmpDir, "ppt", "embeddings")));
```

### Suggested Fix

Only create these directories when the presentation actually contains charts or embedded objects.

## Complete Post-Processing Function

Combining all workarounds into a single reusable function:

```javascript
const { execSync } = require("child_process");
const fs = require("fs");
const path = require("path");

/**
 * Post-process a PptxGenJS-generated PPTX to fix known defects that
 * trigger PowerPoint's "needs to be repaired" and "unreadable content"
 * dialogs.
 *
 * Addresses: phantom Content_Type entries, malformed notesMaster,
 * empty scaffold directories, and unused extension registrations.
 *
 * NOTE: Does NOT fix invalid shape preset strings (oval, roundedRectangle).
 * Those must be corrected in the generation code itself:
 *   "oval"              -> "ellipse"    (or pres.shapes.OVAL)
 *   "roundedRectangle"  -> "roundRect"  (or pres.shapes.ROUNDED_RECTANGLE)
 */
function repairPptx(filePath) {
  const tmpDir = filePath + ".repair-tmp";
  try {
    execSync("rm -rf " + JSON.stringify(tmpDir));
    execSync("mkdir -p " + JSON.stringify(tmpDir));
    execSync("unzip -o " + JSON.stringify(filePath) +
             " -d " + JSON.stringify(tmpDir), { stdio: "pipe" });

    // --- [Content_Types].xml ---
    const ctPath = path.join(tmpDir, "[Content_Types].xml");
    let ct = fs.readFileSync(ctPath, "utf8");

    // Remove phantom slideMaster overrides (Defect 3)
    const mastersDir = path.join(tmpDir, "ppt", "slideMasters");
    const actualMasters = new Set();
    if (fs.existsSync(mastersDir)) {
      fs.readdirSync(mastersDir).forEach(function(f) {
        if (f.endsWith(".xml")) actualMasters.add(f);
      });
    }
    ct = ct.replace(
      /<Override\s+PartName="\/ppt\/slideMasters\/([^"]+)"[^>]*\/>/g,
      function(match, filename) {
        return actualMasters.has(filename) ? match : "";
      }
    );

    // Remove notesMaster/notesSlide overrides (Defect 5)
    ct = ct.replace(/<Override\s+PartName="\/ppt\/notesMasters\/[^"]*"[^>]*\/>/g, "");
    ct = ct.replace(/<Override\s+PartName="\/ppt\/notesSlides\/[^"]*"[^>]*\/>/g, "");

    // Remove unused Default extensions (Defect 4)
    const mediaDir = path.join(tmpDir, "ppt", "media");
    const usedExtensions = new Set(["xml", "rels"]);
    if (fs.existsSync(mediaDir)) {
      fs.readdirSync(mediaDir).forEach(function(f) {
        usedExtensions.add(f.split(".").pop().toLowerCase());
      });
    }
    ct = ct.replace(
      /<Default\s+Extension="([^"]+)"[^>]*\/>/g,
      function(match, ext) {
        return usedExtensions.has(ext) ? match : "";
      }
    );

    fs.writeFileSync(ctPath, ct);

    // --- Strip notes infrastructure (Defect 5) ---
    execSync("rm -rf " + JSON.stringify(path.join(tmpDir, "ppt", "notesMasters")));
    execSync("rm -rf " + JSON.stringify(path.join(tmpDir, "ppt", "notesSlides")));

    var presPath = path.join(tmpDir, "ppt", "presentation.xml");
    var presXml = fs.readFileSync(presPath, "utf8");
    presXml = presXml.replace(
      /<p:notesMasterIdLst>[\s\S]*?<\/p:notesMasterIdLst>/g, ""
    );
    fs.writeFileSync(presPath, presXml);

    var presRelsPath = path.join(tmpDir, "ppt", "_rels", "presentation.xml.rels");
    var presRels = fs.readFileSync(presRelsPath, "utf8");
    presRels = presRels.replace(/<Relationship[^>]*notesMaster[^>]*\/>/g, "");
    fs.writeFileSync(presRelsPath, presRels);

    var slideRelsDir = path.join(tmpDir, "ppt", "slides", "_rels");
    if (fs.existsSync(slideRelsDir)) {
      fs.readdirSync(slideRelsDir).forEach(function(f) {
        if (f.endsWith(".rels")) {
          var rp = path.join(slideRelsDir, f);
          var content = fs.readFileSync(rp, "utf8");
          var cleaned = content.replace(/<Relationship[^>]*notesSlide[^>]*\/>/g, "");
          if (cleaned !== content) fs.writeFileSync(rp, cleaned);
        }
      });
    }

    // --- Remove empty directories (Defect 6) ---
    execSync("rm -rf " + JSON.stringify(path.join(tmpDir, "ppt", "charts")));
    execSync("rm -rf " + JSON.stringify(path.join(tmpDir, "ppt", "embeddings")));

    // --- Re-pack ---
    execSync("rm -f " + JSON.stringify(filePath));
    execSync(
      "cd " + JSON.stringify(tmpDir) +
      " && zip -r -q " + JSON.stringify(filePath) + " . -x '*.DS_Store'"
    );

    console.log("Post-processed: PptxGenJS defects remediated");
  } catch (e) {
    console.error("Post-processing error:", e.message);
  } finally {
    execSync("rm -rf " + JSON.stringify(tmpDir));
  }
}
```

## Diagnostic Approach

If PowerPoint reports repair issues with a PptxGenJS file:

1. **Unpack both files:**
   ```bash
   mkdir orig repaired
   unzip original.pptx -d orig
   unzip repaired.pptx -d repaired
   ```

2. **Diff the structure:**
   ```bash
   diff -rq orig repaired
   ```

3. **Check for invalid shape presets:**
   ```bash
   grep -r 'prstGeom prst=' orig/ppt/slides/ | \
     grep -v '"rect"\|"line"\|"ellipse"\|"roundRect"'
   ```

4. **Check for phantom Content_Type entries:**
   ```bash
   grep -o 'slideMaster[0-9]*\.xml' orig/[Content_Types].xml | wc -l
   ls orig/ppt/slideMasters/*.xml | wc -l
   # If counts differ, phantom entries exist
   ```

5. **Check notesMaster health:**
   ```bash
   # Count placeholder shapes in notesMaster
   grep -c 'p:ph' orig/ppt/notesMasters/notesMaster1.xml
   # If > 0, likely malformed
   ```

6. **Compare element counts per slide:**
   ```python
   import xml.etree.ElementTree as ET
   orig = len(list(ET.parse('orig/ppt/slides/slide1.xml').iter()))
   rep  = len(list(ET.parse('repaired/ppt/slides/slide1.xml').iter()))
   # If repaired has fewer elements, content was removed (invalid shapes)
   # If repaired has more, PowerPoint added missing optional elements (tables)
   ```

A few observations from dealing with similar issues:

1. **The relationship order problem** (rId mismatch) is almost always caused by adding/removing slides or media after the initial relationship table is built. PptxGenJS (and python-pptx) both build the .rels XML incrementally, and if you're doing anything out of order, the IDs can drift.

If you're generating 55-slide decks programmatically, you might also want to look at intermediate representation approaches ΓÇö define the content as structured JSON, then render through an engine that handles the OOXML compliance.
