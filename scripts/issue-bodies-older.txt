```

### Observed Behavior
Aspect ratio is calculated wrong, because it interprets the dimension below 100px as inches and the one above 100px as EMU.
The output srcRect of the code example below is  
```xml
<a:srcRect l="-32635313919" r="-32635313919" t="0" b="0"/>

https://github.com/gitbrent/PptxGenJS/blob/035cf6b26239e2ea1f27eefbcdb8134e504eb4f4/src/gen-utils.ts#L25

When adding a breakpoint here:  
https://github.com/gitbrent/PptxGenJS/blob/035cf6b26239e2ea1f27eefbcdb8134e504eb4f4/src/gen-xml.ts#L65  
the code example below shows the following value for `imgSize`:  
```javascript
imgSize: {w: 2899, h: 88696800}
```

I'd recommend to either allow adding other units when adding w/h values as String, OR don't handle w/h values separately, usually they should use the same unit, OR don't bother converting these values to EMU at all, because they are only used for an aspect-ratio calculation, so the result stays the same, no matter if its inches or emu or something else (but %).

```js
if (options.dataLabelPosition) {
    // ...
    if (options._type === CHART_TYPE.BUBBLE || options._type === CHART_TYPE.BUBBLE3D || options._type === CHART_TYPE.LINE || options._type === CHART_TYPE.SCATTER) {

        if (!['stacked', 'percentStacked'].includes(options.barGrouping || '')) {
            if (!['ctr', 'inBase', 'inEnd'].includes(options.dataLabelPosition))
                delete options.dataLabelPosition;

            if (!['ctr', 'inBase', 'inEnd', 'outEnd'].includes(options.dataLabelPosition))

### [FEATURE] allow user to provide fontScale and lnSpcReduction values with fit: 'shrink'`n### Issue Category

Enhancement

### Product Versions

- Please specify what version of the library you are using......: 3.11.0
- Please specify what web browser you are using.................: Chrome

### Desired Behavior
As explained in [779](https://github.com/gitbrent/PptxGenJS/issues/779), both Powerpoint and Word dynamically calculate a scaling factor and apply fontScale and lnSpcReduction values to a:normAutofit (i.e. {fit: 'shrink'} option). PptxGenJS has no way to trigger this event and calculate the scaling factor. However, there are situation when the user can calculate these values. I suggest allowing user to provide these values. The code could look something like this:
```
if (slideObject.options.fit) {
    if (slideObject.options.fit.type === 'none') bodyProperties += ''
    else if (slideObject.options.fit.type === 'shrink') bodyProperties += `<a:normAutofit${slideObject.options.fit.fontScale ? ` fontScale="${slideObject.options.fit.fontScale}"` : ''}${slideObject.options.fit.lnSpcReduction ? ` lnSpcReduction="{slideObject.options.fit.lnSpcReduction}"` : ''}/>`
    else if (slideObject.options.fit.type === 'resize') bodyProperties += '<a:spAutoFit/>'
}
```
