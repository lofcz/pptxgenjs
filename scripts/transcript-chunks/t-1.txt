Because **nothing in the export stack can emit PowerPoint math**.

PowerPoint’s editable equations are **OMML** (`m:oMath` in the slide XML). What we have today:

| Layer | What it supports |
|---|---|
| **PPTist** | Math as MathLive/LaTeX in HTML (`span.pptist-math` + `data-latex`) |
| **PptxGenJS** | Text runs (`a:t`), images, shapes — **no equations API** |
| **Export** | Rasterize the box (or SVG for `latex` elements) so it *looks* right |

So export has three bad options:

1. **Image** (current) — looks correct, not editable  
2. **Raw LaTeX / plain text** — editable, looks wrong (`\frac`, missing subscripts)  
3. **Real OMML** — not implemented; would need LaTeX→OMML + PptxGenJS support to write `m:oMath`

The `mathPlus` / `mathDivide` stuff in PptxGenJS is just **shape icon names**, not formulas.

**Bottom line:** images aren’t a preference — they’re the only path that preserves layout until someone builds OMML export. That’s a real feature (converter + library work), not a small tweak.

If you want to pursue it, the next step is LaTeX→OMML in PptxGenJS and wiring PPTist to emit those instead of PNGs.

Yes. Mixed text + math is the primary path.

`formatHTML` walks the HTML AST and emits **interleaved runs** in one text box:

- plain text → `{ text: 'Konstantní rychlost: ' }`
- `span.pptist-math` → `{ text: '', options: { omml } }`
- more plain text after → another text run

PptxGenJS puts those in the same `<a:p>`: `<a:r>…text…</a:r>` next to `<m:oMath>…</m:oMath>`. That’s covered by the OMML test (`Speed: ` + fraction) and the export E2E (`Konstantní rychlost: ` + `v=s/t`).

So a line like `Ft = f · Fn` with only the formula marked as math exports as editable equation inline with the surrounding words — not as a full-box image.
